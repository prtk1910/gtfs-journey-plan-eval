# gtfs-journey-plan-eval

Schedule-constrained journey planning: auditing zero-shot LLM itineraries against
exact transit gold.

We ask **stealth/ox-alpha** (via OpenRouter) to plan public-transit journeys on real
GTFS feeds (Portland TriMet, Chicago CTA, Helsinki HSL, NYC Subway) and verify every
leg of every itinerary against the actual timetable. Gold journeys are Pareto-optimal
(arrival × transfers) outputs of a RAPTOR implementation verified against exhaustive
connection enumeration.

## Design

Two context arms separate two hypotheses about failure:

- **closed_book** — the model plans from internal network knowledge alone;
- **schedule_excerpt** — the prompt injects departures at the origin, arrivals at the
  destination, computed single-transfer opportunities (shared or walk-linked stops),
  and full stop-sequences of the next trips through both endpoints with per-stop
  annotations of other serving routes.

Scoring distinguishes *strict* feasibility (every stated minute matches a real
scheduled trip), *lenient* feasibility (route chain exists in the timetable),
reachability, optimality gap vs the gold Pareto front, and a violation taxonomy
(time fabrication, hallucinated routes/stops, impossible arrivals, reasoning
truncation).

## Findings (final run, n=48 audited queries)

- **Closed-book planning is fabrication.** 36% of itineraries reach the destination,
  0% survive strict schedule verification, and 77% of stated arrivals are *earlier
  than the provably optimal journey* — physically impossible outputs that only
  timetable auditing can expose.
- **Schedule evidence trades fabrication for abstention.** With the timetable in
  context, 100% of evidenced queries returned explicit `{"legs": []}` refusals rather
  than unverifiable plans; strict feasibility stayed at 0% in both arms.
- Abstention is network-dependent (rail-dense grids elicit commitment; bus networks
  elicit refusal) and bimodal across sampling paths — single-run evaluations cannot
  see this.

Full manuscript: `PAPER.md` / `PAPER.docx` (regenerated by `make paper`).
The harness is resumable: `make run --n-per-feed N` with larger N grows the dataset,
reusing cached ledger results at zero marginal cost.

## Reproduce

```bash
make setup && make test
make fetch FEED=trimet   # repeat for cta hsl mta
make build FEED=trimet
make gold  FEED=trimet --max-walk-m 300
make run                 # resumable; content-addressed ledger
make paper               # figures + PAPER.md + PAPER.docx
```

Feeds are streamed and reduced to compact Parquet + SQLite indices; raw archives are
kept only as re-build sources (`make clean` removes them). Peak disk < 2GB per feed.
